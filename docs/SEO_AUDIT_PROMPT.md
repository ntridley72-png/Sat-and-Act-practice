# SEO audit prompt — funsat.bid

Hand this whole file to an agent that has web access. It is written to be pasted as-is.

---

## Your task

Audit the live search performance of **funsat.bid**, a free SAT/ACT practice site, and return a
prioritised plan to increase non-paid search traffic.

## Hard rule, read this first

**Never state a ranking, a search volume, a traffic number, or a competitor metric that you did not
read from a named source in this session.** If you cannot measure something, write
`UNKNOWN — needs <specific source>` and move on. An invented position or volume figure is worse
than no figure, because it will be acted on.

For every number you report, give the source and the date you retrieved it. If a source needs
authentication you do not have, say so explicitly and name what the operator must export for you.

Do not pad the report. A short report built on five real numbers beats a long one built on
plausible guesses.

## What the site is

- **Domain:** funsat.bid — free browser-based SAT and ACT practice. No paywall, no signup required.
- **Hosting:** Cloudflare Workers. Static pages generated by `scripts/build-seo-pages.py`.
- **Monetisation:** Google AdSense, publisher `ca-pub-7330416749956065`, `childDirected: true`.
- **Scale:** ~646 URLs in `sitemap.xml`.

Page clusters, by size:

| Cluster | Pages | Pattern | Intent |
|---|---|---|---|
| College profiles | 354 + 50 state hubs | `/colleges/<slug>/` | "university of X sat scores" |
| SAT score lookups | 66 | `/sat-scores/<400-1600>/` | "is a 1200 sat score good" |
| ACT score lookups | 20 | `/act-scores/<n>/` | "is a 28 act score good" |
| Scholarships | 51 | `/scholarships/<slug>/` | brand-name scholarship queries |
| College costs (parent-facing) | 50 + hub | `/college-costs/<state>/` | "cost of college in texas" |
| Unblocked games | 28 + hub | `/unblocked-games/<slug>/` | "<game> unblocked" |
| Guides | 19 | `/guides/<slug>/` | informational long-form |
| SAT↔ACT conversion | 1 | `/sat-act-conversion/` | "sat to act conversion" |
| Landing pages | 4 | `/sat-practice-test/` etc. | head terms |

## Where the real data is

Work through these in order. State which ones you actually reached.

1. **Google Search Console** — the only authoritative source for this site's own impressions,
   clicks, average position and queries. You almost certainly cannot log in. Ask the operator to
   export, for the last 3 and 12 months:
   - Performance → Queries (clicks, impressions, CTR, position), full export
   - Performance → Pages, full export
   - Indexing → Pages report (indexed vs. not indexed, with reasons)
   - Experience → Core Web Vitals
2. **Bing Webmaster Tools** — same, and often grantable faster.
3. **Live SERP checks** — for a short list of target queries, actually search and record what
   ranks. Note the date and that results are personalised/localised. Cap this at ~20 queries;
   it is slow and noisy.
4. **The live site itself** — fetch real URLs and verify what is actually served: titles, meta
   descriptions, canonicals, schema, `robots.txt`, `sitemap.xml`, response codes, redirects.
5. **Third-party estimates** (Ahrefs/Semrush free tiers, similarweb) — label every number from
   these as an *estimate*, because that is what it is. Never present one as measured traffic.

## What to work out

**A. Indexation.** How many of the ~646 URLs are actually indexed? Programmatic clusters commonly
get crawled and then dropped as thin or duplicative. If large numbers are excluded, identify which
cluster and why — that is the highest-value finding available, because unindexed pages cannot rank
at all and no amount of on-page work changes that.

**B. What already ranks.** From Search Console query data, find pages ranking positions 5–20. Those
are the cheap wins: a page at 11 moving to 8 is worth more than a new page. Rank them by
impressions × realistic CTR gain.

**C. Which clusters earn their keep.** Compare clicks per page by cluster. The working hypothesis
to test, not assume: the 354 college profiles are competing against PrepScholar, Niche, CollegeVine
and US News and may generate almost nothing, while the score lookups and guides do the real work.
**Verify this against data and say so plainly if the data contradicts it.**

**D. Technical.** Core Web Vitals on mobile, render-blocking resources, the self-hosted font
preload, sitemap freshness, canonical correctness, mobile usability, structured-data validity
(FAQPage and BreadcrumbList are used widely here — check they parse).

**E. Content gaps.** Given the data assets below, which high-intent queries have no page? Propose
only gaps the site can answer from data it already holds. Available fields per college: admit rate,
SAT/ACT 25th–75th, average SAT, net price, in/out tuition, room and board, median debt, median
family income, loan default rate, 6-year graduation rate, Pell-recipient graduation rate, retention,
median earnings 10 years after entry, first-generation share, student–faculty ratio, setting,
test policy. Plus the official ACT↔SAT concordance and 51 scholarship records.

**F. Off-page.** Backlink profile and realistic link opportunities. For a site like this the usual
ones are school counselor resource pages, teacher link lists, library guides, and student forums.
Be concrete about which, not generic.

## Known constraints — do not recommend against these

- `childDirected: true` is set for compliance reasons. Do not propose removing it.
- Ads are suppressed during practice tests by design. Do not propose adding them there.
- The site is free with no signup. Do not propose gating content.
- Games pages are about games genuinely hosted on the site, not doorways.

## Deliver

1. **Measured baseline** — a table of what you actually retrieved, with sources and dates. Anything
   you could not get, listed as `UNKNOWN` with the exact export needed.
2. **Top 10 actions**, ranked by estimated traffic gain ÷ effort. For each: the specific URL or
   template, the change, why, and how to tell within 30 days whether it worked.
3. **What to stop doing** — any cluster or activity the data shows is not paying for itself.
4. **Open questions** that only the operator can answer.

Flag any recommendation that is a judgement call rather than a data-backed conclusion.
