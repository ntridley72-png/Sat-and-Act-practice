# College verified data: statistics, campus safety, activity photos

Built 2026-10-13. This report states exactly what is verified, how, and what
remains. It does not claim blanket coverage: the federal statistics cover all
354 catalog colleges; campus safety and the new photo categories are a
six-school pilot that must earn its way wider.

## 1. Statistics with provenance (all 354 colleges)

Every displayed metric now carries a machine-readable record in
`college-data.js` (`meta.statsDefs` + per-college `prov` statuses + `bands`)
generated by `scripts/build-college-data.py`:

- value, unit, plain-language definition, documented reporting period,
  population, and source name for each of 23 metrics;
- status per college per metric that distinguishes **reported**, **reported
  as zero**, **privacy-suppressed (PS)**, **not reported (NA/blank)** and
  **coded value not enumerated in the published dictionary**;
- income-band net prices (five bands, public/private variants) with the same
  status handling;
- a visible "Reporting period: … Source: … Checked 2026-10-13" line under
  every statistics table, an "About these numbers" section per page with
  definitions and the non-reported list for that college, and links to the
  College Scorecard data page and its data dictionary.

Sources: College Scorecard Most-Recent-Cohorts-Institution (May 2026 release,
file published 2026-05-26; IPEDS/NSLDS/FSA upstream) and the official
Scorecard data dictionary retrieved 2026-10-13. The `bands` metric allows
net prices by family income where the source reports them.

Known limits, stated on the page: reporting periods follow the dictionary's
documented wording (annual measures roll forward in the release file, so the
file is the newest artifact and the dictionary is the definitional
authority); ADMCON7 code 5 is shown as "unmapped-code" rather than guessed
(the published dictionary enumerates only code 1). 15 colleges report no
income-band net prices at all; 14 have at least one privacy-suppressed
metric. These are labeled, never rendered as zero.

## 2. Campus safety pilot (6 schools, 2022–2024)

Source: the U.S. Department of Education Campus Safety and Security Data
Analysis Cutting Tool (`ope.ed.gov/campussafety`, Clery Act filings), read
through its own web API and cross-checked cell-by-cell (243 cells per
school, zero mismatches) against the Department's official CSV export for
the same calendar years. Institution tables are the sum of their campus rows
in the export — that aggregation rule was verified, not assumed.

Published per school: criminal offenses (including Rape and Fondling
explicitly), VAWA offenses (dating violence, domestic violence, stalking),
arrests, disciplinary referrals, and unfounded crimes — each across four
source geographies kept separate (on campus; on-campus student housing,
labeled a subset, never added; noncampus; public property). The section
carries the Department's own disclaimer plus the required explanation that
these are reported incidents, not prevalence; blank is not zero; and higher
counts do not by themselves mean less safety. Campus support links and three
national confidential resources are listed; every link was fetched (HTTP
200) at build time, and failures are logged in the bundle meta.

Conflicts and unknowns: none between the two ED artifacts. The page does not
publish per-student rates (no defensible population/scope match), does not
merge the housing and on-campus screens, and keeps unfounded counts
separate.

Independent spot-check (2026-10-13): Spelman College's own published Annual
Security Report (2026 edition, Main Campus tables, pp. 42-47) was downloaded
and text-read; every overlapping cell matched the ED bundle - Rape 0/0,
Fondling 1 and 2 for 2023/24, Stalking 3 and 2, Dating violence 0 and 1,
Burglary 4 total. The check is recorded in the bundle's `meta.asrChecks`.
Caveat discovered while checking: Spelman's appendix also carries
per-facility tables for auxiliary student housing (Mix Apartments, ITC,
Gammon Hall) that read all-zero for these categories - those facilities are
separate Clery geography, and the main-campus table is the comparable one.

Source anomaly found by the pipeline's own subset check (2026-10-13):
Oberlin College's filing lists student-housing counts that exceed the
on-campus counts defined to include them - Rape 2022 on campus 1 vs housing
9, and Burglary 2022 on campus 0 vs housing 1. Both ED artifacts (tool data
and CSV export) agree, so the values are published exactly as filed, and the
bundle records them in `subsetAnomalies` with a visible filing note on the
page instead of silently reconciling them. Oberlin is the only school of the
fourteen with such a record.
UH's ASR publishes its statistics as images (no text layer) and App
State's/Williams' ASR pages are bot-walled from this environment, so the
remaining schools keep the two-artifact ED cross-check only.

## 3. Activity and nearby photos (pilot, 14 approved)

Two visibly separate categories with different evidence bars, generated by
`scripts/build-college-photos.py` from Commons geosearch within 10 km of
IPEDS coordinates + curation entries in `scripts/data/college-photo-curation.json`.
Every approved photo passed: geotag distance ≤ 10 miles of the IPEDS campus
point, ≥1000×560 px, JPEG/PNG, reusable license (public domain/CC0/CC BY/CC
BY-SA only), a title naming the place/activity, a visual check by a person,
and a fetched official source proving the venue or recognition.

- Full site build via the wrangler `[build]` command — 646 URLs generated.
- Desktop/tablet/mobile screenshots of the pilot page reviewed
  (`/tmp/clery/pages/` during the session; regenerate with any headless
  runner).

Independent code review (2026-10-13, codex via
`scripts/ai-review-changes.sh --primary opencode`; Claude hit its weekly
limit and returned no report): four findings, all verified against the code
and fixed — (1) the safety cross-check could fail open when the CSV export
was unavailable, so publishing now aborts unless every school cleared a
minimum number of cross-checked cells against a freshly fetched export;
(2) embedded JSON on generated pages is now HTML-safe (`<`, `>`, `&` escaped
in every `<script type="application/json">`, covering Wikimedia-controlled
credit text in both the existing and new galleries); (3) the photo builder
now fetches every official source at build time with a browser user agent
and retries, refusing dead links (404/410) and only honoring a blocked
recheck (403/timeout) when the recorded human verification is under 30 days
old, in which case the recheck outcome is stated visibly in the bundle; (4)
geosearch's hard 500-result cap per campus is disclosed in the rejection log
and curated titles outside the pool now get their distance from the image's
own coordinates instead of being wrongly dropped.

Source-site flakiness worth knowing: Williams College subdomains
(artmuseum.williams.edu, 62center.williams.edu) intermittently answer 403 to
automated clients while serving browsers normally; the last build verified
both at 200, and the blocked-fallback above records the recheck result
whenever a build catches the block instead.

Environment limitations disclosed: the Exa search MCP was rate-limited
(direct official fetches were used instead); outbound browser connections
from this sandbox hang on IPv6-reachable hosts (upload.wikimedia.org,
fonts.googleapis.com), so photo pixels could not render locally —
`college-ui.cjs` now stubs those hosts the same way `college-gallery.cjs`
already did. This does not affect the artifacts' correctness; every image
URL was verified with HTTP 200 and correct content-type via curl.
